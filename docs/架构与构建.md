# 架构与构建

## 项目边界

| 项目 | 职责 |
| --- | --- |
| `src/TouhouLastWorld` | BepInEx 启动、真实 Interop 类型、Harmony 补丁、主表读取、界面恢复和资源适配 |
| `src/TouhouLastWorld.Core` | 业务服务、请求契约、会话、玩家状态、业务路由和存储接口 |
| `src/TouhouLastWorld.Storage` | JSON 文件、临时文件替换、迁移备份、账号文件清理 |
| `src/TouhouLastWorld.Protocol` | 客户端参数转换、响应压缩与加密 |
| `src/TouhouLastWorld.Generators` | 编译期日志生成器 |
| `tests/TouhouLastWorld.Checks` | 正式程序集回归、事务检查和协议样本检查 |

Core 不引用 Unity、Harmony、BepInEx 或 Interop，不直接读写文件。Storage 和 Protocol 引用 Core；插件连接三者。保留插件工程名称和程序集名称，避免改变资源名称及加载入口。

## 请求与业务

```text
NetworkSystemPatch
  → NetworkRequestReader：按接口选择读取器，读取真实 Interop 与主表
  → RequestAdapter：将临时 RequestDraft 转成具体接口输入
  → OfflineServer：构造服务及提供外部入口
  → RuntimeService：会话检查、请求事务、路由与公共响应字段
  → Features/*Service：业务校验、状态变更及响应内容
  → PlayerState → IStateStore → JsonStateStore
```

业务服务通过构造函数明确依赖，不查找全局服务，也不反向依赖 RuntimeService。伙伴、绘卷、设施、任务、战斗、社交等服务各自持有实现。通用库存奖励归 EconomyService，成长统计归 PlayerProgress，账号生命周期归 AccountService，旧档修复归 SeedMigration。

183 个显式业务路由使用各自的输入类型，其他最小响应从 QueryCatalog 注册。支持判断直接查询路由表，不再维护单独的接口白名单。150 个原生请求读取绑定按业务归档；没有参数的接口仍可直接进入服务路由。数字仅表示注册范围，不表示功能完整或真机通过。

Core 中没有 LocalArguments。71 个原先使用万能参数的业务方法已有独立 Command。RequestDraft 仅是 Protocol 和客户端读取器构造输入时的临时容器；它不会进入业务服务。错误的接口输入类型返回 400，未知接口返回 501。

每个游戏目标类仍只有一个 Patch。NetworkErrorRecovery 保留各接口原有的界面恢复与回调差异，不统一强制调用原生回调。

## 状态与兼容

普通请求串行执行。每次操作使用玩家状态工作副本，多次 Save 只更新工作副本；请求成功后只写一次存档。业务拒绝或保存抛错恢复原状态，同时恢复会话和临时剧情编队。时钟使用 TimeProvider，随机源可注入。

账号创建、登录与删除沿用既有身份文件和删除标记的恢复顺序，独立于普通玩家事务。这里不承诺跨多个文件的原子提交。一个服务实例独占一个存档目录，不提供多进程协调。

保留 `user.json`、`account.json`、旧字段和迁移备份名。存档和业务响应继续使用 JSON，以保持现有客户端字段、空值和删除标记兼容。本次不把全部游戏数据改成新对象模型，也不改动奖励公式、掉落范围或未实现接口。这是兼容性选择；新增参数必须使用具体契约，不能把临时参数容器重新引入 Core。

## 构建与检查

在仓库根目录执行：

```powershell
dotnet build TouhouLastWorld.slnx -c Release -p:NuGetAudit=false
dotnet run --project tests/TouhouLastWorld.Checks -c Release --no-build -- src/TouhouLastWorld/user-seed.json tests/Fixtures/protocol-fixture.json
```

本机依赖从 `.local/core`、`.local/interop` 读取，可通过 `BepInExCore`、`InteropDir` 覆盖。上述构建关闭 NuGet 漏洞联网检查。

原有回归拆为 17 组顺序场景，共享少量明确的测试夹具；必须按 Run 中的顺序运行，不能把这些组误当成独立测试。ArchitectureChecks 独立验证整笔回滚、保存失败后重试、时钟注入、输入类型检查和并发更新。

## 部署与真机验证

默认开发构建输出四个 DLL。单 DLL 发布使用源码合编，保留工程分层，无需运行时解包：

```powershell
dotnet build src/TouhouLastWorld/TouhouLastWorld.csproj -c Release -p:BundleSources=true -p:NuGetAudit=false -o deliveries/single-dll
```

该模式只部署 `TouhouLastWorld.dll`，无需复制生成器或其他构建文件。若采用默认开发构建，则一起复制以下四个 DLL：

- `TouhouLastWorld.dll`
- `TouhouLastWorld.Core.dll`
- `TouhouLastWorld.Storage.dll`
- `TouhouLastWorld.Protocol.dll`

Generators 是编译期组件，不部署。2026-11-06 已向手机推送单 DLL 版本并核对 SHA256，未执行游戏流程复验。真机测试状态仍以接口清单为准，文件推送和离线回归不代表画面、资源及游戏流程验证。
